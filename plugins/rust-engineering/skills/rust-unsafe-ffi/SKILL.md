# Rust Unsafe FFI

Own foreign ABI contracts and safe ownership translation across language or runtime boundaries. Apply this profile directly for focused advice or load it from `rust-workflow` as the primary or a supporting profile.

## Use This Skill When

- Rust calls foreign code or exports symbols, handles, buffers, structs, callbacks, or allocators.
- ABI, layout, calling convention, symbol visibility, panic, thread, or foreign lifetime rules need proof.
- Bindings generated by bindgen, cbindgen, CXX, UniFFI internals, or manual declarations need review.

## Workflow

1. Define supported languages, ABI, targets, compiler or runtime versions, ownership, threading, errors, cancellation, and versioning.
2. Model the boundary with fixed representations, opaque handles, explicit lengths, nullable states, and paired allocation or destruction operations.
3. Validate every foreign input before constructing Rust references or values; translate to safe owned or borrowed Rust types inside a narrow wrapper.
4. Prevent unwinding across unsupported ABIs, catch panics at exported boundaries, and map errors to explicit foreign contracts.
5. Define callback registration, invocation threads, reentrancy, context lifetime, deregistration, and shutdown.
6. Test from the foreign side on each supported target and toolchain, including invalid inputs, ownership cycles, panics, and repeated create or destroy.

## Decision Rules

- Use `extern "C"` or the required ABI and `#[no_mangle]` or export attributes deliberately; symbol names are versioned contract.
- Use `repr(C)` only for compatible layouts and fixed-width integer types where size matters.
- A pointer plus length must prove null policy, alignment, allocation extent, element initialization, lifetime, and mutability before slice creation.
- Never free memory with a different allocator or runtime than created it; provide paired APIs when ownership crosses.
- Foreign strings need explicit encoding, termination, length, ownership, and embedded-null policy.
- Do not let Rust panics unwind through C or another runtime unless the exact ABI explicitly supports it.
- Opaque handles should validate null, liveness, type, thread affinity, and double-destroy behavior according to contract.
- Callbacks require a stable context object and a race-safe rule for invocation during deregistration and shutdown.

## Boundaries and Hand-offs

- `rust-unsafe` owns raw-pointer and validity proof shared with internal unsafe operations.
- `rust-uniffi-building` owns UniFFI-specific UDL or proc-macro scaffolding and language binding workflows.
- Use `rust-workflow` when the task includes implementation across the repository.
- Use `rust-review` for read-only findings and `rust-verify` for command evidence.
